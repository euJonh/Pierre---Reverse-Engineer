Pierre Design System

Este documento reúne os tokens, componentes e o sistema de widgets da home extraídos do APK do Pierre (CloudWalk). A interface é React Native/Expo, estilizada com NativeWind v4 sobre primitivas gluestack-ui. Todos os valores vêm do bundle Hermes v98 decompilado. Os espécimes abaixo foram recriados em HTML a partir desses valores.

Fonte Geist Marca #CFFF04 NativeWind rem = 14 Tema dark forçado 8.743 classes compiladas

Legenda: O observado literalmente no código · I inferido. O app define LIGHT_MODE_DISABLED = true, então em produção fica sempre escuro. A paleta clara existe e pode ser vista pelo seletor abaixo.

Cores e temas

THEME_TOKENS é exportado com o hook useThemeColors(), que devolve a paleta do modo atual com isDark. O NativeWind expõe as mesmas cores como variáveis CSS (--background, --pierre, --surface…). Os swatches mudam com o seletor de tema.

Tipografia

A UI usa só a Geist (@expo-google-fonts/geist 0.4.1), com Regular e Medium carregados primeiro. As classes font-* trocam a família (Geist-Medium, Geist-Bold…) e mantêm fontWeight: '400'. Como o rem é 14, a escala do Tailwind fica 12,5% menor que o normal, e text-sm foi redefinido para 16 px, ficando maior que text-base.

Glass e blur

Anatomia de um widget

  • Container: bg-surface r24 (GlassContainer clear só no iOS 26).
  • half: p-4 gap-2, chevronRight 16 em #71717a.
  • wide: título text-lg muted, valor text-2xl font-extrabold, subtítulo text-base.
  • Vazio: ícone wifiOff, “Sem dados disponíveis”.
  • Erro: feedbackWarning #EF4444, “Falha ao sincronizar dados”.
  • Loading: shimmer com opacidade .3 ↔ .7 em 800 ms, blocos #71717a.
  • Tap: háptico Light e navegação para a rota do widget.

Edição de widgets

O fluxo de edição é implementado por VisionJiggleWrapper, VisionSortableWidgetGrid e VisionWidgetContextMenu. Ele imita a edição da tela inicial do iOS: tremor, botão de remover no canto e redimensionamento por arraste.

Entrar no modo de edição

  1. Segurar 500 ms háptico Medium · bloqueia o tap por 1200 ms · abre o menu de contexto em top = max(12, y − 140), left = min(max(12, x − 100), W − 212)
  2. Continuar segurando +1500 ms o menu fecha, háptico Heavy, enterEditMode, a tab bar some. Evento edit_mode_entered {widget_count}
  3. Ou tocar em “Editar widgets” no menu de contexto
  4. Sair “Concluído” no header de edição. Evento edit_mode_exited {widget_count, did_reorder}

Adicionar widget

  1. Painel de controle tela vision/add-widget, título 28/32 peso 400, busca com placeholder “Novo Widget”. Uma seção por widget com previews de cada tamanho; seção “Agentes” para widgets de IA. Estado vazio: “Sua home já está completa”.
  2. Detalhe widget-detail?id=&size=: pager de tamanhos com pontos (ativo 24×8, inativo 8×8) e botão “Adicionar Widget” variant pierre (lime, texto preto, ícone calcCircleAdd).
  3. Confirmação toast “<label> adicionado”, showWidget, setWidgetSize, PATCH em /api/mobile/vision/layout.
  4. Widget com IA chat “Criar widget” (placeholder “Envie uma mensagem”) → “Adicionar widget”. Id ai-<uuid>, só tamanho half. Menu com “Remover da home” e “Apagar permanentemente”.

Evidências e limites

  • Artefato: Pierre.apk (214 MB), app config v4.0.6, bundle assets/index.android.bundle em Hermes bytecode v98, decompilado com hermes-dec 0.1.8 (versão 98 não é oficialmente suportada pela ferramenta).
  • As referências Lnnnn apontam para linhas do pseudo-JS decompilado. É análise estática: nada foi executado em aparelho.
  • Os espécimes são recriações em HTML/CSS. Glass e blur nativos foram aproximados, e no Android o app usa os fallbacks sólidos.
  • Não foi verificado, widget por widget, qual componente (Widget2x2/WidgetWide/WidgetFull) cada um usa em cada tamanho, nem a animação de entrada do menu de contexto.
  • Atkinson, Inter e Roboto vêm de SDKs nativos (inferido: não há referência no JS).
